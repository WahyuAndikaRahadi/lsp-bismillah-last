## Scope dan peran

Satu LSP per deployment, tanpa tenancy. Tiga role canonical lower-case: `admin`, `asesor`, `asesi`. Registrasi publik hanya asesi. Asesor mengakses peserta yang ditugaskan langsung kepadanya, bukan semua peserta pada jadwal yang sama. Asesi hanya objek miliknya.

Kepala Bidang Sertifikasi, Ketua TUK, koordinator, tim teknis/komite, Kabag Administrasi, dan pimpinan adalah **fungsi SOP**. Simpan orang nyata, fungsi, dasar penunjukan, masa berlaku, dan actor pencatat/pengesah pada jadwal/pleno/keputusan. Admin dapat menjalankan fungsi administrasi sesuai penunjukan langsung tersebut; tidak ada generic capability/assignment portal. Pengesah keputusan harus orang yang berwenang pada rekaman penunjukan dan bukan asesor peserta itu. Tidak diperlukan role keempat. Anggota eksternal harus memiliki bukti tindakan/kehadiran nyata, bukan dibuatkan actor fiktif.

SOP 04 §1.4 memerlukan verifikasi asesor/tim asesor ditetapkan. Kolom Admin LSP pada APL-01 tetap berasal dari tindakan administrasi nyata. Pemeriksaan administratif admin dan review asesor tampil pada satu detail permohonan; upload lengkap bukan otomatis memenuhi syarat.

**Hapus dari aplikasi aktif:** complaints, staff/capability portal, finance, chat/messages, generic letters, quality, proxy/impersonation, dan PDF export. **Keputusan perubahan owner:** alur lean banding (appeals), surveilans (surveillance), resertifikasi (recertification), dan ketidakberpihakan (impartiality) sekarang **IN SCOPE** karena penting bagi sertifikasi dan dipersyaratkan SOP (SOP 07, 01, 04 §4–5, 19) melalui task 21-01 sampai 21-04. Desain lean: attributable records berstatus ringkas, independensi investigator/reviewer (tidak pernah terlibat kasus), kerahasiaan, ketertelusuran, actor dan event nyata, tanpa hasil otomatis. Roles tetap tiga: `admin`, `asesor`, `asesi`. Fungsi independen dicatat sebagai penunjukan orang nyata. AK-04 adalah intake resmi feeding penanganan banding 21-01. SPT asesor, SPT verifikasi TUK, penunjukan komite, dan keputusan adalah record core, tanpa modul surat umum.

## Shortcut

Wajib event nyata, actor dan timestamp server, audit trail, serta koreksi berwenang tanpa menghapus riwayat. Tidak boleh menciptakan K/BK, jawaban, observasi, consent, hadir atau keputusan.

**Auto-signature:** asesi memberi satu consent eksplisit saat bergabung jadwal; asesor sekali saat menerima penugasan. Simpan teks/versi scope semua dokumen jadwal, signature version/hash, actor, timestamp. Checkbox tidak preselected. Approval asesor tidak menciptakan consent asesi. Aplikasi menautkan signature otomatis pada record yang memiliki tindakan sah; tidak menandatangani record kosong seolah telah diputuskan. Persetujuan AK-01 atas rencana aktual adalah event berbeda; perubahan substansial rencana membutuhkan acknowledgment baru, tanpa upload signature ulang.

Revocation memblokir penerapan berikutnya. Admin hanya dapat mencatat koreksi/pencabutan beralasan dengan bukti, bukan consent pengganti. Dokumen historis mempertahankan event/signature lama beserta koreksi; perubahan profil tidak mengubahnya.

**Kehadiran:** asesi tercatat pada POST `Masuk ruang uji` dalam tanggal/rentang sesi timezone jadwal setelah semua prasyarat. Asesor pada penyimpanan instrumen/observasi pertama hari itu, atau POST `Mulai sesi asesmen` untuk kerja pengawasan nyata. GET, login, consent dan penugasan bukan hadir. Idempotent per orang/sesi; koreksi admin mempertahankan event asal. Pleno berasal dari partisipasi nyata/bukti tervalidasi, bukan undangan.

**Sertifikat:** admin berwenang upload file privat setelah keputusan positif sah assessment terkait. Nomor, tanggal terbit, berlaku mulai/hingga dan nomor blanko (pernyataan pemegang) berasal dari dokumen nyata; jangan default tiga tahun. Asesi memiliki banyak sertifikat melalui banyak assessment. Upload berarti tersedia; download terotorisasi dengan file tersedia mencatat akses/penyerahan digital, bukan bukti transfer browser selesai. FR-10.2 membedakan upload, download dan acknowledgment penerimaan nyata; tidak mengisi penerimaan saat upload admin.

**Data:** kosong adalah draft/pending, bukan otomatis `-`, `N/A`, `0`, tanggal hari ini atau lulus. N/A hanya bila field mengizinkan, dengan alasan/reviewer; tidak untuk melewati kompetensi/consent/keputusan wajib. Profile reusable, snapshot assessment immutable.

## Alur minimal

- Asesi: registrasi → profil sekali → jadwal/consent → APL-01/02 → revisi bila diminta → persetujuan AK-01 → masuk ruang uji → tugas asesi → hasil/AK-03 → pengajuan AK-04 (bila mengajukan banding, ditangani independen) → semua sertifikat/acknowledgment/download → pelaporan surveilans & pengajuan resertifikasi terhubung.
- Asesor: penugasan/consent → review APL → MAPA/AK-07/AK-01 → sesi → bukti/temuan → AK-02 → AK-05/06 → paket review.
- Admin: referensi/TUK → jadwal/asesor/koordinator → pemeriksaan administratif/pengecualian → BA → pleno/keputusan → upload sertifikat.

Satu next action per halaman; tidak ada redirect berantai atau semua tombol formulir ditumpuk. Detail UI ada pada [PAGE_CONTRACT](PAGE_CONTRACT.md).
